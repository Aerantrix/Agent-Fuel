How the experiment works

The agent gets a task and a tool, and the tool is broken on purpose. Two numbers are measured: how many tokens the agent burns after the failure, and whether the controller halts healthy work by mistake.

ScenariosNine: six with a failed service, two healthy tasks that must not be halted, one reference task.evaluation/scenarios.json
Fault harnessA stub analytics service that fails on command. No real service is called.sandbox/fake_tools.py
Agent loopThe model decides, the program calls the tool, the model reads the result.agent/runner.py
Model providerSends the conversation to the model and gets back the reply and token counts.call_model, parse_action
ControllerGives a verdict on every step: allow, warn or stop. Arms A–G switch mechanisms on one at a time.control/agent_fuel.py
Result filesThe frozen database and the files computed from it.console/data/runs.jsonl, results/
Control codes: A no control · B account limit · C iteration cap · D run budget · E + loop detector · F + circuit breaker · G Agent Fuel (all). The paper names them in words. All external tools are stubs with controllable failure modes. No live service was called.
